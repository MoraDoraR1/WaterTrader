# 선박 3D 모델 제작 가이드 (`ship.js`)

이 문서는 바다상인(WaterTrader) 프로젝트의 선박 3D 모델이 어떻게 만들어지는지, 그리고 사용자가 직접(또는 다른 AI를 통해) 디자인을 수정하려면 무엇을 알아야 하는지 정리한 기술 가이드입니다.

## 핵심 사실: 모델링 툴이 아니라 "코드로 그린 도형"입니다

이 게임의 선박은 Blender 같은 3D 모델링 툴에서 만든 `.glb`/`.fbx` 파일을 불러오는 방식이 **아닙니다**. 대신 `web/src/entities/ship.js`의 `buildShipMesh(shipDef)` 함수가 실행될 때마다 Three.js의 기본 도형(박스, 원기둥, 압출 도형 등)을 코드로 하나씩 조립해서 배 모양을 만듭니다. 그래서:

- 형태를 바꾸려면 **좌표/치수 숫자를 바꾸는 코드 수정**이 필요합니다. 마우스로 정점을 드래그하는 방식이 아닙니다.
- 장점: 선박 20종·소형/중형/대형/초대형 4등급·모험/교역/전투 3역할 조합을 숫자 몇 개로 자동 생성할 수 있습니다.
- 단점: 아주 세밀하거나 유기적인 형태(조각 같은 곡선, 정교한 장식)는 코드로 표현하기 번거롭습니다.

**만약 "내가 원하는 모양을 자유롭게 조각하듯 만들고 싶다"**면, 아래 "대안: 외부 3D 모델 가져오기" 섹션을 먼저 읽어보시길 권합니다. 지금 방식(코드 수정)보다 훨씬 직관적일 수 있습니다.

---

## 1. 좌표계/축 변환 규칙 (가장 헷갈리는 부분)

배는 로컬 좌표계 기준으로 다음과 같이 정의됩니다:

- **+Z = 이물(뱃머리/bow)**, **-Z = 고물(선미/stern)**
- **+X = 우현**, **-X = 좌현**
- **+Y = 위쪽(하늘 방향)**

선체 윤곽선(`outline` 배열, `ship.js:87`)은 "위에서 내려다본 평면도(top-down)"를 `[x, z]` 쌍으로 정의합니다. 이걸 실제 3D 벽처럼 세우기 위해 `ExtrudeGeometry`로 압출한 뒤 `.rotateX(-Math.PI / 2)`를 적용하는데, 이 회전은 `(x, y=압출깊이, z)` 순서를 `(x, 압출깊이, -y)`로 바꿉니다. 그래서 코드에서 이렇게 씁니다:

```js
outline.forEach(([x, z], i) => {
  if (i === 0) hullShape.moveTo(x, -z); else hullShape.lineTo(x, -z);
});
```

**`z`가 아니라 `-z`를 넣는 이유가 바로 이 회전 때문**입니다. 새 도형을 이 방식(윤곽선 → 압출 → rotateX(-90°))으로 만들 때는 항상 이 부호를 지켜야 합니다. 잘못 넣으면 배가 뒤집히거나 거울상으로 만들어집니다.

## 2. 전체 구조 한눈에 보기

`buildShipMesh()`는 위에서 아래 순서가 아니라 **아래(용골)에서 위(돛대)** 순서로 부품을 하나씩 `group.add(...)` 합니다. 전체 흐름(대략적인 코드 줄 번호는 수정하면서 바뀔 수 있으니 참고용):

| 부품 | 설명 | 핵심 변수 |
|---|---|---|
| ① 선체(hull) | 갑판 아래 솔리드 몸통 | `hullLen`, `hullWid`, `hullHei`, `outline` |
| ② 선저 테이퍼(bilge) | 흘수선 아래, 용골 쪽으로 좁아지는 쐐기 | `bilgeGeo.scale(x, 1, z)` |
| ③ 용골(keel) | 이물/고물로 휘어 오르는 곡선 골재 | `keelCurve` (CatmullRomCurve3) |
| ④ 뱃전(bulwark) | 갑판 위로 둘러선 **속이 빈 링** 벽(난간부) | `bulwarkHole`, `holeScale`, `bulwarkH` |
| ⑤ 레일 캡 / 웨이스트 레일 | 뱃전 위·중간을 두르는 트림 몰딩 | `railCapGeo`, `waistRailGeo` |
| ⑥ 갑판(deck) | 뱃전 안쪽 바닥 판 | `deckGeo.scale(...)`, `deckY` |
| ⑦ 포문(gunport) | 좌우 측면 포문 + 밝은 테두리 | `addGunportRow()` |
| ⑧ 화물(교역용) | 궤짝/술통 | `cargoSpots` |
| ⑨ 선수루(forecastle) | 이물 쪽 낮은 갑판 구조물 + 난간 | `forecastleH`, `castleScale` |
| ⑩ 선미루(quarterdeck+poop) | 고물 쪽 2단 구조물 + 창/랜턴 | `qdH`, `poopH`, `addSternGallery()` |
| ⑪ 방향타/닻 | | `rudder`, `anchorGroup` |
| ⑫ 돛대+활대+돛(마스트) | 다단(하/중/상) 돛대, 가로돛 또는 라틴세일 | `mastCount`, `tierCount`, `addLateenRig()` |
| ⑬ 선수사장(bowsprit)+스프릿세일 | | `bowsprit`, `spritGeo` |
| ⑭ 깃발 | 국가색 깃발(선미, 대형 전투선은 이물에도) | `flag`, `bowFlag` |

전체 치수는 `shipDef.class`(소형/중형/대형/초대형, `SHIP_CLASSES`에 정의된 `hullScale=[sx,sy,sz]`)와 `shipDef.role`(모험/교역/전투)에 따라 자동으로 스케일됩니다. 즉 **하나의 함수가 배 20척 전부를 만듭니다** — 개별 배마다 별도 코드가 있는 게 아닙니다.

## 3. 자주 바꾸게 될 파라미터

### 크기/비율
```js
const hullLen = 10 * sz;                 // 선체 길이
const hullWid = 3.4 * sx * roleHullMul;  // 선체 폭 (역할별 배수 포함)
const hullHei = 2.2 * sy;                // 선체 전체 높이 기준값
```

### 갑판 함몰(옴폭 파인 정도)
```js
const deckY = hullHei * 0.48;   // 갑판 바닥 높이 (낮을수록 더 깊이 파임)
const bulwarkH = hullHei * 0.44; // 뱃전(난간 벽) 높이 (높을수록 벽이 두드러짐)
const holeScale = 0.6;           // 뱃전 안쪽 구멍 크기 (작을수록 벽이 두꺼워지고 갑판이 좁아짐,
                                  // 클수록 벽이 얇아지고 갑판이 넓어짐)
deckGeo.scale(0.5, 1, 0.5);      // 갑판 바닥판 크기 (holeScale보다 항상 작게 유지해야 함)
```

### 선체 윤곽(배의 실루엣)
`outline` 배열의 각 점을 조정하면 선체 모양 자체가 바뀝니다. 예를 들어 선미 트랜섬 폭(`hw*0.22`)을 넓히면 고물이 더 뭉툭해지고, 줄이면 더 뾰족해집니다.

### 색상
파일 상단/각 섹션에서 색을 헥스 코드로 직접 지정합니다. 예: `'#96693c'`(오크색 상부 선체), `'#1c140b'`(타르 먹인 하부), `'#e6c15a'`(금색 트림).

## 4. 로컬에서 확인하는 방법

이 세션(Claude)이 사용하는 방식과 동일합니다:

```bash
cd web
node build-artifact.mjs   # dist/bada-sangin-standalone.html 생성
```

생성된 `dist/bada-sangin-standalone.html`을 브라우저로 그냥 열면 바로 게임이 실행됩니다(별도 서버 불필요, 단일 HTML 파일). `ship.js`를 수정할 때마다 이 명령을 다시 실행해서 확인하면 됩니다.

더 빠른 반복을 원하면 `npx serve web`으로 `web/index.html`을 열어 개발 모드(import map 기반, 번들링 없음)로 확인할 수도 있습니다.

## 5. 대안: 외부 3D 모델(Blender 등) 가져오기

코드로 숫자를 조정하는 대신, **자유로운 형태 조각**을 원한다면 이 방법이 더 적합할 수 있습니다:

1. Blender(무료)나 다른 3D 툴에서 배 모델을 원하는 대로 제작합니다.
2. `.glb`(GLTF Binary) 형식으로 내보냅니다. (Three.js 생태계에서 가장 표준적인 포맷)
3. 이 프로젝트에 `GLTFLoader`를 추가해 `.glb` 파일을 불러와 `buildShipMesh()`가 반환하던 `THREE.Group` 대신 사용하도록 코드를 바꿔야 합니다. (현재는 이 로더가 프로젝트에 없습니다 — 필요하면 제가 붙여드릴 수 있습니다.)
4. 다만 이 프로젝트는 **하나의 자기완결형 HTML 파일**(다운로드 없이 아티팩트로 배포)로 빌드되기 때문에, `.glb` 파일도 Base64로 인코딩해 HTML 안에 함께 넣어야 합니다. 파일 크기가 커지면(수 MB) 아티팩트 용량 제한(16MB)에 걸릴 수 있으니 저폴리로 제작하시는 걸 권장합니다.

이 방식을 원하시면 말씀해 주세요 — GLTFLoader 연결과 빌드 스크립트(`build-artifact.mjs`)의 Base64 임베딩 부분을 제가 미리 세팅해드리면, 이후로는 Blender에서 내보낸 파일을 교체하기만 하면 됩니다.

## 6. 다른 AI에게 이 작업을 맡길 때 전달할 정보

다른 AI(또는 다른 Claude 세션)에게 이 파일 수정을 요청하실 때는 아래를 함께 전달하시면 정확도가 높아집니다:

- 수정 대상 파일: `web/src/entities/ship.js`의 `buildShipMesh()` 함수
- 이 문서(`web/docs/SHIP_MODEL_GUIDE.md`) 전체 내용
- **원하는 변경사항을 최대한 구체적으로**: "포문을 더 크게", "돛대를 3개에서 2개로", "선수루를 완전히 제거" 등. 스크린샷이 있으면 함께 전달하면 훨씬 정확합니다.
- 빌드 확인 방법(`node build-artifact.mjs`)도 함께 알려주면, 그 AI가 스스로 결과를 검증할 수 있습니다.
